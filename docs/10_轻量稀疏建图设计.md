# 10 轻量稀疏建图设计（v0.2.3 默认流程）

## 1. 目标

把默认建图从“渲染整张高分辨率拼图”改成：

1. 只在清晰、稳定、有足够重叠时拍摄；
2. 每次只保存 1200px 关键帧、ORB/边缘特征、位姿、覆盖多边形；
3. 用**全部已拍关键帧的覆盖并集**告诉操作员“哪里拍过、还差哪里”；
4. 用稀疏关键帧数据库完成实时定位；
5. **每拍一张立即并入低分辨率总览**，不攒到最后再拼；
6. 全图扫描保留为独立备用模式。

这解决了低配电脑上整图渲染的内存/耗时问题，也避免“整图拼接错位后全部标注都失效”。但**不等于不需要视觉地图**：稀疏关键帧就是地图，只是不再保存全部像素。

## 2. 数据模型

```text
工程/
  project.pcbproj.json
  project_assets/
    global_board.png          # 增量低分辨率总览（默认 ≤3200px / 8MP）
    sparse_map.json           # 关键帧位姿、覆盖、邻居、图像索引
    sparse_features.npz       # 拼接后的 ORB 关键点/描述子、偏移、全局描述子
    keyframes/
      kf_0000.jpg             # 1200px 关键帧
      kf_0001.jpg
      ...
```

`sparse_map.json`：

```json
{
  "version": 1,
  "board_width": 1578,
  "board_height": 640,
  "features": "sparse_features.npz",
  "keyframes": [
    {
      "index": 0,
      "shape": [1000, 1600],
      "pose": [[0.8, 0, 0], [0, 0.8, 0], [0, 0, 1]],
      "coverage": [[0, 0], [1000, 0], [1000, 750], [0, 750]],
      "neighbors": [1],
      "image": "keyframes/kf_0000.jpg"
    }
  ]
}
```

- `pose`：关键帧图像像素 → 板总览像素。
- `coverage`：该关键帧在板坐标中的四角多边形。
- `neighbors`：由覆盖多边形相交关系补全，用于未来回环/路径规划。
- 描述子采用 `npz` 拼接 + `offsets`，不依赖 pickle，加载更安全。

工程 JSON 新增：

```json
{
  "sparse_map": "demo_assets/sparse_map.json",
  "map_mode": "hybrid"
}
```

`map_mode`：

- `full`：旧工程/全图扫描工程，只用全图跟踪；
- `hybrid`：轻量工程默认，稀疏定位 + 低分辨率全图周期校验；
- `sparse`：只用稀疏定位（当前 UI 未单独提供，保留给低算力场景）。

## 3. 捕获流程

### 3.1 稳定检查

每 110ms 取一帧：

- 缩放到 800px 宽，灰度；
- Laplacian 方差作为清晰度；
- 与上一帧做 `cv2.phaseCorrelate`，估计位移；
- 清晰度 ≥10、位移 ≤3px 连续 2 帧 → 稳定。

稳定后：

- 第一张自动拍摄（可取消勾选）；
- 后续必须手动“拍摄当前区域”，避免连续误拍。

### 3.2 红色覆盖

每次预览：

```text
当前帧 ORB -> 上一关键帧 ORB
若上一张失败 -> 再试更早的已拍关键帧（最多 5 个候选）
RANSAC 求 T_current→candidate
Pose_current = Pose_candidate · T_current→candidate
所有历史 coverage 多边形 · Pose_current⁻¹ -> 当前画面
```

把**所有**关键帧的 coverage 多边形投影到当前画面，再合并成一个 `QPainterPath` 一次性填充；重叠区域不会因为 alpha 叠加而变深。红色区域就是“全部已拍关键帧的覆盖并集”。

- 红色完全消失：与上一关键帧无匹配/无重叠，拒绝拍摄；
- 红色 >82%：移动太少，拒绝拍摄；
- 红色 10%~82% 且稳定：允许拍摄。

**红色本身只是提示**，是否允许拍摄还取决于 ORB 内点（≥14）和清晰度，避免“红色画错但看起来有重叠”。

v0.2.2 增加了**覆盖证据门控**：

- 除当前匹配来源关键帧外，每个投影到当前画面的旧关键帧都必须与当前帧重新做 ORB/RANSAC；
- 实测变换与历史位姿推出的期望变换比较，位移 >22px、旋转 >4°、尺度差 >8% 就排除；
- 每次最多复核 3 张旧关键帧，避免预览过慢；
- 被排除的旧 coverage 不画红，宁可少画也不假红；
- UI 在捕获状态显示“已复核 N 张”。

这不是结构树，但先阻止“旧位姿漂移导致整块假红”。结构树方案见 [结构特征树与覆盖可信度](12_结构特征树与覆盖可信度.md)。

v0.2.3 再加一层**红区面积/外形记忆**：

- 每次拍摄保存红区面积比例、连通域数、bbox、外形 Hu；
- 下一帧把上次红区 mask 按位姿 warp 过来，计算面积变化率和 IoU；
- 面积突增、IoU 过低、外形 Hu 突变、红区碎裂，连续 2 帧异常就禁止拍摄；
- 阈值：面积增长 >45%、IoU <0.35、外形距离 >1.15；
- UI 显示“红区面积/外形：稳定/波动/异常”。

它是快速 guard，不替代 ORB 证据门控，也不替代结构树。

### 3.3 拍摄与位姿

拍摄时重新在 1200px 图像上提取 ORB（与保存图像一致）。位姿估计优先用**所有可能重叠的旧关键帧**，而不是只累计上一张：

```text
对每个候选旧关键帧 kf_old：
    T_new→old = ORB/RANSAC(new, old)
    pose_candidate = pose_old · T_new→old
选内点最多且几何有效的候选
若都不足，回退：
    pose_kf = pose_current_full · diag(1/s, 1/s, 1)
```

其中 `s` 是 1200px 关键帧相对当前实时帧的缩放。这样做能减少“只能相对上一张累加”造成的漂移。保存：

- JPEG（质量 90）；
- 关键帧关键点/描述子/全局边缘描述子；
- 位姿；
- 覆盖多边形；
- 时间戳、内点数。

### 3.4 每拍一张立即合并

每次 `capture()` 成功后立即执行：

```text
新关键帧位姿 -> 低分辨率总览坐标
必要时扩展总览画布（并保留原内容）
把新关键帧 warp 到总览
按覆盖并集/羽化与旧内容混合
把新覆盖多边形并入 coverage_mask
更新右侧“增量总览”缩略图
```

- 总览默认缩放 0.8，最多 3200px / 800 万像素；
- 新区域直接写入；重叠区域按 55% 混合，避免覆盖掉更早的有效像素；
- 画布扩展时复制旧总览和覆盖 mask，不清空；
- 若板太大超过上限，会整体降低总览缩放后重放关键帧（少数情况）；
- 操作员每拍一张都能在右侧看到当前拼接结果，发现错位可以立即重拍。

### 3.5 完成建图

完成时**不再重新拼接所有关键帧**：

- 直接使用已经增量生成的总览；
- 把关键帧位姿和覆盖多边形换算到当前总览坐标；
- 重算邻居关系；
- 打包 `SparseMap` 保存。

因此完成动作通常只需几十毫秒；主要工作已经分摊到每次拍摄。

总览只是“人类可读的板图”，不参与默认稀疏定位。

### 3.6 边缘对齐与板边拉正

人工移动不可能完全水平/垂直，摄像头也不可能每次都严格在局部正上方。v0.2.1 增加了两级补偿：

1. **每张合并前做 ECC 边缘对齐**
   - 在已有总览与新关键帧的**重叠区**上做；
   - 用 Canny 边缘（板边、丝印、走线、焊盘）而不是背景颜色；
   - 只估计小范围 Euclidean 位移/旋转，限制 24px / 2.5°；
   - 相关系数低于 0.18 或变换越界就放弃，避免把好图拉坏；
   - 校正会写回关键帧位姿，后续稀疏地图保持一致。

2. **完成后按板体外轮廓拉正**
   - 用绿色/彩色板体掩膜找最大轮廓，取最小外接矩形；
   - 用单应变换把板子拉成横平竖直的矩形，背景不参与；
   - 同时把所有关键帧位姿左乘该单应，保证稀疏定位坐标一致；
   - 板边没有完整进入总览（≥2 侧贴边）时跳过，避免把背景拉进来；
   - UI 的“完成后按板边拉正（推荐）”可关闭。

这能修正整板旋转/透视、局部刚性错位和接缝，但**不能**：

- 凭图像把任意走线恢复成 CAD 直线；
- 修复没有重叠、没有纹理区域的错位；
- 替代回环闭合/位姿图优化。

因此仍有接缝时，先看右侧增量缩略图补拍；下一步才是重叠区 ECC/相位精修 + 回环闭合。

## 4. 稀疏定位

### 4.1 检索

- 当前帧缩放到 1200px，CLAHE + ORB（1800 特征）+ 32×32 边缘全局描述子；
- 候选顺序：
  1. 上一帧命中的关键帧（连续跟踪时命中率最高）；
  2. 全局描述子 Hamming 距离 top-4；
- 对候选做 KNN + ratio 0.76 + `estimateAffinePartial2D`；
- 内点 ≥14，选分数最高者；若上一关键帧内点 ≥40，可提前结束以降低耗时。

### 4.2 坐标变换

```text
T_live_full→kf = T_live_work→kf · diag(s_live)
T_live→board   = pose_kf · T_live_full→kf
T_board→live   = inverse(T_live→board)
```

用板中心为支点做相似变换平滑（α=0.65）；快速跳变/重捕时跳过平滑。

### 4.3 状态与回退

- 连续帧失败 ≤8：`stale`，保持上一矩阵；
- 超过：`lost`，隐藏覆盖层；
- 下一帧重新检索关键帧，可重捕。

## 5. 稀疏 + 全图混合（HybridTracker）

```text
每帧：
  sparse_result = sparse.track(frame)
  每 10 帧或 sparse 失败：
      full_result = full.track(frame)
  两者都 locked：
      计算板中心在实时帧中的位置差
      >24px 且 full 置信度足够 -> 用 full
      否则用 sparse
  sparse 失败、full locked -> full
  两者都失败/暂失 -> 保留可用的 stale 矩阵
```

- 全图跟踪器运行在**低分辨率总览**上，不加载大拼图。
- 默认使用稀疏结果，保证轻量；
- 全图每 10 帧做一次全局一致性校验；
- 稀疏因重复纹理误锁时，全图可纠正；
- 稀疏失败时，全图兜底。

状态栏显示 `稀疏定位` / `全图增强`，并显示内点、置信度、耗时。

## 6. 与“黑白矢量线条”方案的关系

本实现没有保存一张黑白大图，而是保存更接近工业视觉的“稀疏特征图”：

| 需求 | 本实现 |
|---|---|
| 去除颜色/光照干扰 | CLAHE + ORB 二值描述子 + 边缘全局描述子 |
| 低存储 | 每关键帧约 100KB JPEG + ~70KB 特征；100 帧约 17MB |
| 快速定位 | 只匹配上一关键帧 + top-k，不逐像素比整图 |
| 几何校验 | RANSAC 相似变换 + 覆盖多边形 |
| 定位失败可解释 | 红色覆盖/内点/置信度/全图校验 |
| 参数识别 | BOM/人工；不由形状推断 |

黑白边缘图仍可用于可视化/粗筛，但不足以单独承担定位：

- 重复焊盘/走线会产生大量相似局部；
- 反光/烧黑会改变二值阈值；
- 不同板型必须重新建图；
- 元件阻值/容值不能从形状推出。

## 7. 存储与性能估算

| 数据 | 估算 |
|---|---|
| 一个 1200px JPEG 关键帧 | 80~150 KB |
| 2200 个 ORB 描述子 | 70 KB |
| 100 个关键帧 | 约 15~25 MB |
| 增量总览（≤8MP） | 约 4~24 MB 内存，PNG 2~10 MB |
| 旧全图（例如 100MP） | 约 300 MB 原始 + 渲染临时内存 |

本机短序列实测：

- 3 关键帧 → 1578×640 增量总览；每张拍摄后立即更新，收尾约 0.02 s；
- 稀疏定位约 50~60 ms/帧；
- 混合跟踪默认稀疏，每 10 帧一次全图校验。

## 8. 失败模式与现场处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 红色完全消失 | 移动过快/无重叠/纹理不足 | 回退，让红色重新出现再拍 |
| 红色 >82% | 移动太少 | 移动到新区域 |
| 画面未稳定 | 手抖/运动模糊/曝光变化 | 停稳 0.3~0.5 s 再拍 |
| 关键帧特征不足 | 空白/纯色/过曝 | 对准丝印/焊盘/连接器 |
| 稀疏定位误锁 | 重复焊盘 | 全图校验会纠正；保留定位孔/连接器在视场 |
| 全图校验也失败 | 总览质量差/关键帧覆盖不足 | 重新捕获；补拍盲区 |
| 总览局部错位/重影 | 关键帧位姿误差、纹理重复 | 看右侧增量缩略图；回退补拍；保留定位孔/丝印；后续回环闭合 |
| 增量总览被重置/变小 | 板超出 3200px/8MP 上限触发降采样 | 正常保护；降低相机分辨率或分段建图 |

## 9. 迁移与兼容

- v0.1 全图工程：`sparse_map` 为空，`map_mode=full`，行为不变。
- v0.2/v0.2.1 轻量工程：`sparse_map` 指向 `sparse_map.json`，`map_mode=hybrid`；v0.2.1 的总览改为逐张增量合并。
- 打开工程时若稀疏地图缺失/损坏：提示并回退全图跟踪，不阻塞打开。
- “另存为”会整体复制 assets（总览、稀疏 manifest、特征 npz、keyframes）。
- 全图扫描仍通过原入口创建 `map_mode=full` 工程。

## 10. 后续增强

1. 回环闭合：关键帧邻居图 + 覆盖重叠，检测回到已拍区域，做位姿图优化。
2. 覆盖质量报告：总览上标出空洞、重叠率过低、模糊关键帧。
3. 稀疏地图压缩：按信息量裁剪特征，进一步降低存储。
4. 全图增强升级：从关键帧生成更高分辨率总览，并保持板坐标映射；把独立全图工程与轻量地图合并。
5. 接缝自检：每张合并后用重叠区相位相关/ECC 校正局部平移，进一步减少错位。
6. 机台模式：XYZ 坐标直接给出初始位姿，稀疏/全图只做校验。
7. YOLO/OCR：在总览和实时帧上给类别/位号候选，人工确认参数。
