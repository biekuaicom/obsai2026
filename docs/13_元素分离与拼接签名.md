# 13 元素分离与拼接签名（v0.8.1）

## 1. 目标

拼接不能只靠 ORB 内点。PCB 的重复引脚、重复焊盘会让“点对点匹配”认错位置。  
v0.8.0 在每个关键帧上先分离元素，再用元素中心和尺寸/方向做二次对齐：

```text
关键帧
  → 元件、焊盘、孔、文本、走线、色块
  → 每个元素保存 bbox/中心/尺寸/方向/颜色/局部描述子
  → 拼接时用元素对应做 RANSAC
  → 再用重叠区边缘/灰度内容核对
```

元素签名同时写入 `elements_manifest.json`，后续元件识别可以直接裁小图块，不需要每次从整板重新找。

## 2. 当前分离基线

`src/pcb_ar/core/seam_elements.py` 是**经典分割基线**，不是训练好的语义分割模型：

| 元素 | 当前方法 |
|---|---|
| 元件本体 | 复用结构基元的元件候选 |
| 焊盘 | 高亮/低饱和金属区域 |
| 孔 | Hough 圆 |
| 走线 | Canny + HoughLinesP |
| 文本 | MSER 小连通区域 + 尺寸/长宽比过滤 |
| 色块 | HSV 非绿色大面积连通域 |

每个元素保存：

```text
kind / bbox / center / angle / area / color / 12×12 灰度描述子
```

限制：

- 文本没有 OCR，只有形状/位置；
- 焊盘和色块可能重叠；
- 元件边缘只露出一半时，尺寸可能偏小；
- 复杂板/低对比度需要换真正的分割模型。

## 3. 元素匹配

`match_elements(reference, query, initial)`：

1. 用 ORB 初值把 query 元素中心变到 reference 坐标；
2. 只匹配同类型元素；
3. 面积比限制 0.3~3.0，允许边缘半截元件；
4. 最近邻一对一，RANSAC 估计相似变换；
5. 内点数 ≥6 才接受。

该矩阵只允许小幅修正 ORB：与 ORB 的平移差 ≤6px、旋转差 ≤0.8°、尺度差 ≤2% 才采用，且至少 2 类元素。超过阈值视为重复纹理误配，只作为内容分加分，不覆盖 ORB。  
最终候选分数：

```text
(ORB 内点 + 1.5 × 元素内点) × 重叠内容分
```

## 4. 与红色区域的关系

红色区域是共同覆盖区的显示。  
元素匹配只在两张图实际重叠的范围内工作；红区稳定是前提，元素对齐是进一步约束。

## 5. 输出

轻量工程创建时写入：

```text
工程_assets/elements_manifest.json
```

内容：

```json
{
  "keyframes": [
    {
      "index": 0,
      "width": 1200,
      "height": 760,
      "counts": {"component": 3, "pad": 1, "hole": 33, "text": 15, "line": 49, "color": 2},
      "elements": [
        {"kind": "text", "bbox": [120, 240, 30, 12], "center": [135, 246], "area": 360}
      ]
    }
  ]
}
```

不保存元素像素，只保存位置/形状；后续识别可按 bbox 从关键帧裁图。

## 6. 为什么现在不做直线网格形变

共同红区 + 元素对齐 + 内容核对已经能压住大部分拼接错位。  
网格形变会引入新的非刚性变形，当前阶段先不做；等真实板卡样本证明残余误差确实来自局部弯曲，再上直线约束网格。

## 7. 后续替换成真正分割模型

保持接口不变，替换 `extract_elements` 即可：

```python
def extract_elements(image) -> ElementSet:
    ...
```

推荐顺序：

1. 先收集本项目真实关键帧和元素 bbox；
2. 用轻量分割/检测模型（YOLO-seg / U-Net / SAM 微调）输出 mask；
3. 把 mask 转成 bbox/中心/方向/描述子；
4. 匹配层、拼接层、manifest 不需要改。

这样识别模型只需要处理小图块，速度快，也便于后续元件分类。
