# 12 结构特征树与覆盖可信度

## 1. 先解释“没拍过也变红”

当前红区不是逐像素判断“这张照片有没有覆盖这里”，而是：

```text
所有关键帧的 coverage 矩形
   × 当前位姿的逆变换
   → 投影到当前画面
   → 取并集涂红
```

这有三个结构性缺陷：

1. **coverage 是整帧矩形**，包含黑边、背景、失焦区域；
2. **没有像素证据**：只要历史位姿被信任，整块矩形就会涂红；
3. **误差会传递**：后面关键帧的位姿由前面累加；某一张漂了，整块旧矩形就盖到新区域上。

所以“越到后面越容易出现整块误红”是符合当前逻辑的：后期关键帧更多、覆盖矩形更多，任何一个历史位姿漂移都会贡献一大块假覆盖。

v0.2.2 先止血：**红区必须由当前帧直接匹配复核**；v0.2.3 再加红区面积/外形记忆 guard。

## 2. 已实现的覆盖证据门控

预览时：

```text
当前帧 ORB
  → 找最佳关键帧源
  → 对每个投影后与当前画面相交的旧关键帧：
       当前帧 ORB 与旧关键帧 ORB 重新匹配
       RANSAC 估计当前帧→旧关键帧
       与历史位姿推出的期望变换比较（位移/旋转/尺度）
       匹配不足或变换不一致 → 不画它的 coverage
  → 只对通过复核的关键帧取红区并集
```

限制：

- 除来源关键帧外，每次最多复核 3 张旧关键帧；
- 位移差 >22px、旋转差 >4°、尺度差 >8% 就排除；
- UI 显示“已复核 N 张”，红区不再无条件信任整帧矩形；
- 仍然保留“来源关键帧”的覆盖（它本身就是当前匹配源）。

这能挡住“旧位姿漂移导致整块假红”，但它只是**几何一致性复核**，不是结构语义识别。

### 2.1 建议保留的快速 guard：红区面积/外形记忆

你的“每拍一张记录红区面积 + 外形值，超出正常波动判误识别”是合理且便宜的，v0.2.3 已把它实现为**快速 guard**，但不要作为唯一判据。

每个预览可计算：

```text
red_area_px / red_area_ratio
连通域数量、最大连通域面积
bbox、centroid、extent（面积/bbox）
solidity（面积/凸包面积）
Hu moments / 轮廓周长 / 圆形度
与上一帧红区（经位姿 warp 后）的 IoU
面积变化率 d(area)/frame
```

判定：

- 面积突增 >25%、突减 >45%；
- IoU <0.45；
- 连通域数量突变；
- 外形 Hu/长宽比超出记忆区间。

只做**告警或短暂禁止拍摄**，不要直接永久拒绝。因为：

- 回到旧区域时红区面积合法增大；
- 视场变化会改变外形；
- 面积/外形无法区分“真覆盖”与“整块假红”。

因此建议组合：

```text
面积/外形 guard（毫秒级，每帧）
  + ORB 证据门控（每帧）
  + 结构树（拍照/完成时，按需）
```

面积/外形计算在 1600×1000 掩膜上通常只需 1~3ms，普通 PC 可以全程运行；结构树提取只在关键帧/完成时做，避免每帧做图匹配。

### 2.2 结构树仍然必须保留

面积/外形只能判断“红区是否异常”，不能回答“这个元件是什么、引脚/焊盘/定位孔对不对”。所以二维码式结构树仍要保留，用在：

- 整图生成后的单元件识别；
- 元件外形、引脚阵列、焊盘、过孔、丝印文本的相对关系；
- 多元件组合交叉验证；
- 关键帧检索和位姿校验。

两者不是二选一：

- **面积/外形记忆**：覆盖是否可信的快速体检；
- **结构树**：元件/引脚/焊盘/文本的语义识别与交叉验证。

## 3. 借鉴二维码，但不能照搬

二维码可靠的原因：

- 有固定的寻像图形/校正图形；
- 有设计好的网格和编码规则；
- 有 Reed-Solomon 纠错；
- 黑白对比和模块尺寸受控。

PCB 不是设计好的二维码：

- 元件可能缺失、换型、遮挡；
- 丝印/焊盘有反光、氧化、烧黑；
- 同型号板的不同版本可能有相同局部；
- 走线不是固定网格，圆弧/斜线很多；
- 背景和板体颜色随光线变化。

因此**不能承诺数学意义上的 100%**。能做到的是：

- 高精度结构匹配；
- 多假设交叉验证；
- 置信度不足时拒绝覆盖/要求人工确认；
- 用统计指标衡量误红率，而不是宣称绝对正确。

## 4. 结构特征树设计

### 4.1 基元提取

从每张关键帧提取“稳定、可重复”的基元：

| 基元 | 提取方式 | 过滤 |
|---|---|---|
| 元件本体 | 大块暗色/矩形连通域，边缘闭合 | 面积、长宽比、边缘支持度 |
| 引脚/焊盘 | 小矩形阵列、等间距重复 | 间距一致性、面积范围 |
| 定位孔/安装孔 | 圆/环，Hough 圆或轮廓圆度 | 圆度、孔径范围 |
| 长走线 | LSD/FLD 线段，长度/方向 | 长度、边缘对比、剔除短噪点 |
| 大色块/丝印 | 大面积统一色块、文字块 | 面积、颜色方差 |
| 文本 | 可选 OCR/连通字符组 | 仅作为辅助，不作为唯一依据 |

小杂乱点、渐变、反光高光、背景纹理**不进入结构树**，只保留稳定基元。

### 4.2 基元描述子

每个基元归一化为：

```text
type, center(x,y), size(w,h), aspect, angle,
area_ratio, edge_strength, color_bin,
neighbor_distance[], neighbor_angle[], neighbor_type[]
```

不存原始像素，只存“形状 + 相对位置 + 关系”。

### 4.3 结构树

```text
Level 1：单个元件 + 它相对最近焊盘/过孔/丝印的局部关系
Level 2：两个元件的距离、角度、尺寸比
Level 3：三个元件组成的三角形/共线关系
...
Level N：整块板的结构图
```

匹配时不是只认一个元件，而是：

1. 先用 Level 1 找候选；
2. 用 Level 2/3 的边关系交叉验证；
3. 用 Level N 的全局结构做一致性检查；
4. 多组假设 RANSAC/图匹配，保留最高置信度；
5. 置信度不足 → 不更新位姿/不画覆盖。

### 4.4 容错

二维码用固定纠错码；PCB 结构树只能用**统计容错**：

- 允许节点缺失/遮挡（例如 20% 元件不可见）；
- 尺寸/角度用区间而不是精确值；
- 允许多个相似候选，交给上层时序/覆盖证据裁决；
- 对重复焊盘阵列，要求至少两个不同尺度的结构同时成立；
- 失败时明确“未确认”，不要假装已覆盖。

## 5. 与现有流程的接入顺序

### Phase A（已完成，v0.2.2 / v0.2.3）

- 红区来源必须通过当前帧 ORB + 历史位姿一致性复核；
- UI 显示已复核关键帧数；
- 红区面积/连通域/bbox/外形 Hu 与上次拍摄记忆比较；
- 连续两帧异常则禁止拍摄；
- 挡住整块旧矩形误红。

### Phase B（下一步）

- 新增 `structural_map.py`：
  - 基元提取、过滤、归一化；
  - 每关键帧结构描述子；
  - 结构树序列化到工程 assets。
- 先用于**关键帧检索和覆盖验证**，不直接替换 ORB 位姿。

### Phase C

- 结构树图匹配 + 多假设位姿；
- 与 ORB、ECC、全图跟踪融合；
- 回环闭合/位姿图优化；
- 覆盖栅格记录每个 cell 的证据来源，红区只显示高置信 cell。

## 6. 覆盖可信度模型

建议把覆盖从“矩形并集”改为“证据栅格”：

```text
board_grid[x,y] = {
    valid_pixels,          # 来自哪些关键帧
    evidence_count,        # 独立匹配证据数
    structural_support,    # 结构树支持
    last_seen,
    confidence
}
```

显示规则：

- `confidence >= high`：红色“已拍”；
- `medium`：黄色“疑似已拍，需确认”；
- `low/none`：不画红。

这样即使某张关键帧漂了，也不会把整块新区域涂成红色；错误会退化成“未确认”，而不是“假已拍”。

## 7. 验收指标

不要用“100%”验收，用可测量指标：

| 指标 | 目标 |
|---|---|
| 假红率（未拍区域被标红） | < 1%（逐步降低） |
| 漏红率（已拍区域未标红） | 可接受略高，宁可漏红不可假红 |
| 关键帧检索 top-3 命中率 | > 95% |
| 结构树匹配召回（遮挡/缺件） | > 85% |
| 定位重捕时间 | < 1 s |
| 误锁率（错误位姿仍 locked） | 接近 0，必要时拒绝 |

## 8. 结论

你的方向是对的：**用形状、相对位置和多层组合做结构识别**，比单纯 ORB 更接近“看懂板子”。

但工程上要分两步：

1. 先把“红区 = 有证据的覆盖”做对，阻止整块假红；
2. 再引入结构树，做多假设、交叉验证和置信度拒绝。

当前 v0.2.3 完成第 1 步（ORB 证据门控 + 面积/外形 guard）；第 2 步结构树需要真实板卡的关键帧/位姿/覆盖数据来调参和验证。没有真实样本，直接写一套“100% 结构树”只会把误判从红区转移到别处。
