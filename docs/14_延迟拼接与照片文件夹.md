# 14 延迟拼接与照片文件夹（v0.9.0）

## 1. 为什么改成延迟拼接

旧流程每拍一张就：

```text
warp 新关键帧
  → 混合总览
  → 曝光补偿
  → 全画布 distanceTransform
  → 更新缩略图
```

画布越大，单次拍摄越慢；到 9×5 张时，拍照阶段本身就被拖慢，还容易把中间错误直接固化进总览。

v0.9.0 默认改为：

```text
拍照阶段：
  保存 JPEG + ORB/位姿 + 板面 coverage mask
  → 不混合图像像素
  → 只更新红区/覆盖

完成阶段：
  统一按位姿预拼
  → ECC 局部对齐
  → 接缝源选择（每个像素只留一层）
  → 结构/元素签名
  → 输出总览
```

## 2. 拍照阶段

- 每张关键帧 JPEG 保存在内存；
- 只维护板坐标 coverage mask 和红色预览；
- 不做图像 warp/混合/曝光/distanceTransform；
- 右侧缩略图显示“完成后统一拼接”；
- 拍照耗时基本不随已拍张数增加。

## 3. 完成阶段

1. 按关键帧位姿预拼；
2. 每张关键帧对已有内容做重叠区 ECC；
3. 接缝源选择，保证同一像素只保留一层；
4. 板面 mask 排除白纸；
5. 生成 `overview`；
6. 提取结构基元与元素签名；
7. 返回 `photos` 列表。

## 4. 照片文件夹

工程创建时写入：

```text
工程_assets/photos/
  kf_000.jpg
  kf_001.jpg
  ...
```

主界面「文件 → 导出拍照文件夹…」可复制整个文件夹。  
`elements_manifest.json` 记录每个关键帧的元素 bbox/类型，后续识别模型可直接裁小图块。

## 5. 当前边界

- 完成阶段仍然是一次批量渲染，张数很多时需要等待，但不再卡拍照；
- 预拼仍依赖关键帧位姿，严重错位需要回拍/补拍；
- 还没有做 CAD 式全局吸附/网格形变；
- 没有真实 800 万像素硬件验收。

## 6. 后续

- 完成阶段加“元素/直线约束的全局吸附”；
- 多层重叠区域做 seam graph；
- 把批量渲染放到独立线程/进度条；
- 真实板卡上验证白纸 mask 和元素匹配阈值。
