# 02 算法设计

> **v0.2 默认流程已改为轻量稀疏建图。** 本文第 1 节的全图跟踪、第 2 节的全图视频扫描仍保留，作为备用/增强模式；默认捕获、稀疏关键帧定位和红色覆盖门控见 [轻量稀疏建图设计](10_轻量稀疏建图设计.md)。

本文描述当前实现的实际算法、参数和失效边界。代码位置与符号：

- `M`：2×3 相似变换矩阵，方向为 **全局图坐标 → 实时帧坐标**。
- `(u,v) = M · (x,y,1)ᵀ`。
- 相似变换包含等比缩放 `s`、旋转 `θ`、平移 `(tx,ty)`；不允许反射/剪切。

## 1. 实时局部-全局配准（GlobalLocalTracker）

### 1.1 预处理与特征

1. 全局图按 `global_match_width=1800` 等比缩小，CLAHE 增强后提取 ORB（`nfeatures=5000`）。这一步只在打开工程/初始化跟踪器时做一次。
2. 实时帧按 `live_match_width=1200` 缩小，同样 CLAHE + ORB（`nfeatures=1600`）。
3. 为什么不对 4K 原图直接匹配：特征数、描述子距离计算和 RANSAC 都会随像素数增长；AR 叠加不需要 4K 级定位，1200 工作宽度在本机可达到约 43~50 ms/帧。

### 1.2 匹配与变换估计

```text
des_live --KNN(k=2)--> des_global
ratio test: m.distance < 0.76 * n.distance
estimateAffinePartial2D(global_pts, live_pts,
                        RANSAC, ransacReprojThreshold=4px)
```

`estimateAffinePartial2D` 只求解 4 自由度（等比缩放、旋转、平移），比完整单应性更抗重复纹理和噪点。

工作尺度矩阵还原到原始坐标：

```text
M_full = diag(1/s_live) · M_work · diag(s_global)
```

再通过 SVD 投影到最近的纯相似变换：

```text
A = U S Vᵀ, R = U Vᵀ, s = mean(S)
M = [sR | t]
```

### 1.3 质量门控

以下任一条件失败，本帧不更新，进入 `stale/lost`：

| 条件 | 当前阈值 | 目的 |
|---|---|---|
| 有效匹配数 | ≥ 18 | 防止特征不足 |
| RANSAC 内点 | ≥ 12 | 防止少数错误匹配控制结果 |
| 相似性校验 | 无反射、基向量近正交、长度接近 | 排除剪切/翻转 |
| 尺度跳变 | 相对上一帧 ≤ 2.2× | 排除错误匹配/变焦异常 |
| 旋转跳变 | ≤ 28° | 排除错误匹配 |
| 重投影中位误差 | ≤ 7.2 px（1.8×ransac） | 排除“形似但错位” |
| 映射区域与视口重叠 | ≥ 12% | 排除完全跑出画面 |
| 连续丢失 | > 8 帧则 `lost` | 避免长期显示错误位置 |

### 1.4 平滑策略

直接对矩阵元素做 EMA 会因旋转中心远离原点导致明显拖尾。实现采用 **以全局图中心为支点** 的插值：

```text
p_prev = A_prev · c + t_prev
p_curr = A_curr · c + t_curr
p_smooth = (1-α)p_prev + α p_curr
θ_smooth, s_smooth 分别做角度展开/对数插值
M_smooth = similarity(s_smooth, θ_smooth) 且 M_smooth·c = p_smooth
```

- `α=0.65`（可配置）。
- 当中心位移 > `max(70px, 6% 画面宽度)`、旋转 > 5° 或尺度变化 > 10% 时，**本帧直接使用原始矩阵**，避免快速移动时标注拖尾几十像素。

### 1.5 跟丢与重捕

- 匹配失败：`lost_frames += 1`；若已有上一矩阵且未超上限，状态 `stale`，继续显示最后位置（透明度降低）。
- 超上限：状态 `lost`，矩阵置空，UI 隐藏覆盖层。
- 下一帧仍然做全图匹配，不依赖上一位置，所以重新进入有纹理区域后可自动恢复。恢复后的第一帧会因“大变化”绕过高斯平滑，立即对齐。

### 1.6 已知失效模式

- **重复纹理**：大量相同去耦电容/规则焊盘可能导致错误匹配。当前用 RANSAC + 内点阈值缓解，但不能完全消除。建议保留定位孔/丝印/连接器等非重复特征在视场内。
- **运动模糊**：曝光时间长、移动快时 ORB 失效；应提高快门/频闪或放慢移动。
- **大面积反光/纯色**：特征不足，需调整环形光/偏振片。
- **明显透视/倾斜**：相似变换无法拟合；需要单应性或相机标定。
- **镜头畸变**：边缘区域误差增大；建议远心镜头或先做畸变校正。

## 2. 全图连续视频扫描（VideoScanSession，备用/增强）

### 2.1 核心假设

相邻视频帧重叠 80%~90%；只估计“当前帧 → 上一关键帧”的小变换：

```text
T_cur_last = estimateAffinePartial2D(cur_pts, last_kf_pts)
Pose_world(cur) = Pose_world(last_kf) · T_cur_last
```

### 2.2 处理流程

```text
frame
 ├─ 清晰度检查（Laplacian 方差 ≥ 14；低于则拒绝并提示）
 ├─ ORB 特征（工作宽 1200）
 ├─ 与上一关键帧 KNN + ratio 0.78
 ├─ 内点 ≥ 16；尺度变化 ≤ 1.35×；重叠 ≥ 18%
 ├─ 位姿累加
 ├─ 位移 ≥ 100px 或旋转 ≥ 1.4° → 接受为新关键帧
 │    （或位移 ≥ 12px 且距上一关键帧 ≥ 1.2s）
 └─ 关键帧：1280 宽 JPEG(q=92) + 位姿 + 时间戳 + 内点
```

- 关键帧只存 JPEG，避免几十张 1600×1000 原图占满内存。
- `1280` 宽关键帧在渲染时把世界坐标同步缩放，最终拼图保持原生分辨率，不做“用低清图强行放大”。
- 单次扫描最多 120 个关键帧；渲染最多 12000 边长、9000 万像素，超出则统一缩放。
- 扫描 UI 每 240 ms 抓取当前实时帧；重复帧跳过。

### 2.3 拼图渲染

扫描结束后不再重新做全局匹配，直接使用保存的位姿：

1. 解码全部关键帧；
2. 将扫描世界坐标乘以 `world_scale = 关键帧宽 / 原始帧宽`；
3. 计算所有图像四角的联合包围盒；
4. 逐张 `warpAffine` 到局部 ROI；
5. 用距离变换生成羽化 alpha，先覆盖未覆盖区域，再在重叠区渐变融合；
6. 裁掉未覆盖黑边。

这比“每张图与全局图做一次 SIFT 匹配”快得多，也避免重复焊盘导致的错误全局匹配。

### 2.4 漂移与回环

相机轨迹是一串相似变换的连乘，误差会累积：

```text
Pose_n = T_1 · T_2 · ... · T_n
```

当前版本的控制手段：

- 高重叠（相邻帧位移 100px，约 92% 重叠）；
- 位姿质量门控；
- 关键帧间隔不过大；
- 拼图时不做二次匹配，避免引入新的跳变。

**尚未实现**：

- 回环闭合（最后一张与第一张匹配并分配误差）；
- 位姿图优化 / bundle adjustment；
- 多圈扫描的全局一致性。

工程建议：按区域分块扫描，或扫描完检查拼图接缝；长板扫描后人工确认关键区域。后续可在 `video_scan.py` 增加回环候选与 `scipy.optimize`/g2o 位姿图。

### 2.5 实测

在 3200×2200 合成板上扫描 80 个连续视图（1600×1000，步进 45px），阈值 100px：

- 关键帧：28；
- 拼图：2689×1203；
- 渲染：约 3.2 s（本机 CPU，含解码/羽化；修复画布角点计算后实测）；
- 关键帧相对真值平均四角误差 < 1 px（短序列，无回环）。

真实板因纹理、曝光、运动模糊，数值会更差。

## 3. 散图拼接备用路径（stitcher.py）

用于“已有若干局部照片，无法重新扫描”的场景。

1. 相邻/前序图片用 SIFT 特征（5000 点）+ ratio 0.7 匹配。
2. RANSAC 求 `B → A` 部分仿射。
3. 校验：重叠面积 ≥ 8%，梯度图重叠相关系数 ≥ 0.30，相似变换合法。
4. 逐张配准，允许回溯更早的图；选得分最高的前序图。
5. 按累计变换渲染、羽化。

**为什么用 SIFT 而不是 ORB**：合成板和真实 PCB 上有大量重复焊盘；ORB 在实测中曾把相邻图错配到其他元件。SIFT 的尺度和描述子更稳健，配合梯度相关性校验后，重复纹理错配显著减少。代价是慢（8 张图约 10 s），因此只作为备用。

## 4. 自动候选检测（detector.py）

默认检测器不识别类别，只找“可能是元件”的矩形：

1. 缩放到工作宽 2000。
2. 用颜色先验构造非板材掩膜：`G - max(R,B) < 12` 或灰度 < 40；去除纯白丝印（≥208），避免把板名文字当元件。
3. 形态学开（5×5）去噪、闭（7×7）聚合本体与焊盘。
4. `findContours(RETR_LIST)`：深色板框会形成整幅外轮廓，必须取内部轮廓。
5. 过滤面积（0.014%~7.5%）、宽高、长宽比、填充率、边缘距离、圆形度（定位孔/安装孔）。
6. NMS（IoU 0.35）+ 按行排序。

合成板测试：28 个元件中约 23~27 个被框到，另有少量过检/粘连。**它只是候选生成器**，必须人工核对。

### YOLO 适配器

`YoloDetector` 按 Ultralytics 接口实现，但未随安装包捆绑 `ultralytics/torch`（会把包体推到 GB 级）。若训练了权重：

```python
from pcb_ar.core.detector import YoloDetector
det = YoloDetector("weights/pcb_best.pt", class_names=[...], confidence=0.25)
dets = det.detect(global_image)
```

需要额外安装 `ultralytics`，并在数据集中覆盖真实相机、光照、反光、遮挡。详见 [硬件集成与演进](06_硬件集成与演进.md)。

## 5. 参数与调优

参数集中在：

- `pcb_ar/config.py` 的 `AppConfig`（用户可改 `%LOCALAPPDATA%\PCB_AR_Annotator\config.json`）；
- `pcb_ar/core/tracker.py` 的 `TrackerConfig`；
- `pcb_ar/core/video_scan.py` 的 `ScanConfig`。

| 现象 | 优先调整 |
|---|---|
| 跟踪慢 | 降低 `tracker_global_features`、`tracker_live_features`、`live_match_width` |
| 跟丢多 | 提高特征数、降低 `tracker_ratio`（如 0.72，更严格）、降低最小内点 |
| 标注抖动 | 提高 `tracker_smoothing`（如 0.75），但会增加一帧延迟 |
| 快速移动拖尾 | 平滑已对大变化自动跳过；可进一步降低分辨率/提高帧率 |
| 扫描拼图错位 | 降低移动速度、提高重叠、降低 `keyframe_translation_px` |
| 扫描内存大 | 降低 `keyframe_max_width`、`max_keyframes` |

## 6. 参考公式汇总

```text
像素坐标变换:        q = M · [p,1]ᵀ
相似矩阵:            M = [s cosθ  -s sinθ  tx]
                         [s sinθ   s cosθ  ty]
矩阵复合:            Pose_world(cur) = Pose_world(last) · T(cur→last)
扫描世界缩放:        Pose' = diag(k,k,1) · Pose,  k = W_keyframe / W_source
框四角投影:          q_i = M · [x_i,y_i,1]ᵀ
气泡锚点（屏幕）:    由 view.mapFromScene 投影框角，在视口内做碰撞避让
```
