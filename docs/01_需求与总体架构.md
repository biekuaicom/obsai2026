# 01 需求与总体架构

## 1. 背景与目标

项目希望在电路板正上方安装相机（当前为手动显微镜，未来迁移到 XYZ 机台），实现：

1. 通过摄像头识别 PCB 上的元件并自动给出候选标注；
2. 人工核对/修正元件参数；
3. 在实时画面中把矩形框、引线和参数“钉”在电路板物理位置上；
4. 显微镜手动平移、旋转、上下变焦时，标注同步跟随；
5. 先完成 Windows 桌面版，最终封装为可分发程序。

### 1.1 关键硬件假设

- 相机光轴基本垂直板面；手动阶段允许小角度旋转（±5° 量级）和小幅 Z 变化。
- PCB 是平面；不存在明显柔性弯曲/倾斜。
- 视场内有定位孔、焊盘、丝印和固定连接器，可提供稳定特征。
- 相机分辨率约 800 万像素；实际处理会降采样，避免 4K 全分辨率计算。
- 显示屏与操作员在同一侧，操作员可同时移动显微镜并观察叠加标注。

### 1.2 本版边界

本版是可运行 MVP，不包含：

- 真实相机/显微镜的现场精度验收；
- 语义级元件分类（默认检测器只产生候选框）；
- 完整回环闭合/SLAM；
- XYZ 机台串口/网口协议；
- 多用户、数据库服务端、云同步；
- 自动生成 BOM 或自动判定元件好坏。

## 2. 功能需求

| 编号 | 需求 | 本版实现 |
|---|---|---|
| F1 | 实时画面 | USB 摄像头、视频文件、合成演示源 |
| F2 | 建图 | 默认轻量引导捕获（关键帧/稀疏地图/低分辨率总览）；全图视频扫描备用/增强 |
| F3 | 局部-全局定位 | 默认稀疏关键帧 ORB + RANSAC；低分辨率全图周期校验/回退 |
| F4 | AR 标注 | 随板旋转的框、屏幕可读参数气泡、引线 |
| F5 | 自动候选 | 传统颜色/形态学检测；YOLO 适配器接口 |
| F6 | 人工核对 | 画布气泡最多 3 参数；右侧完整参数与扩展字段 |
| F7 | 状态流 | 待核对/已核对/异常；下一待核对 |
| F8 | 数据持久化 | JSON 工程 + 全局图，保存备份 |
| F9 | BOM | CSV 导入/导出 |
| F10 | 打包 | PyInstaller onedir + 离线自检 |

## 3. 非功能需求

- **实时性**：目标 10~20 FPS；跟踪单帧 < 80 ms；界面不因匹配卡死。
- **可读性**：参数气泡不随缩放变小；框随板旋转，但文字始终水平。
- **鲁棒性**：局部遮挡、短暂跟丢时保持最后位置；连续丢失后隐藏覆盖层并可重捕。
- **数据安全**：保存采用临时文件+原子替换；旧文件保留 `.bak`。
- **隔离性**：源码依赖只装进项目 `.venv`；用户数据写 LocalAppData。
- **可演进**：核心算法与 UI 解耦；未来接 XYZ 轴/串口时不改 UI。

### 4.1 线程模型

- **UI 线程**：Qt 控件、绘图、工程数据修改、扫描对话框。
- **LiveWorker（QThread）**：阻塞式摄像头读取 → 降采样 → 调用跟踪器 → 发 `frame_ready` 信号。
- **MosaicBuildThread（QThread）**：扫描完成后解码关键帧、渲染拼图，避免 UI 冻结。
- 工程数据只在 UI 线程修改；LiveWorker 只读 `HybridTracker`（稀疏定位 + 全图跟踪）的内部状态。启动新源前先停止旧线程，避免并发访问。
- **SparseBuildThread（QThread）**：轻量捕获结束后生成低分辨率总览和稀疏地图，避免 UI 冻结。
- 信号跨线程传递 `numpy.ndarray` 是安全的（Qt 队列连接，Python 对象引用）。

### 4.2 显示与坐标

| 坐标系 | 含义 | 用途 |
|---|---|---|
| 全局图像素 `(gx,gy)` | 拼接后的整板图坐标 | 工程数据持久化、元件框 |
| 实时帧像素 `(ux,uy)` | 当前相机/视频帧坐标 | 绘制背景、鼠标交互 |
| 屏幕像素 | `QGraphicsView` 视口坐标 | 气泡布局、编辑器定位 |
| 物理 mm | 全局像素 × `mm_per_px` | 侧栏显示、未来机台 |

跟踪器输出 **全局图 → 实时帧** 的 2×3 相似变换 `M`。所有元件框、引线起始点均通过 `M` 变换；参数气泡是顶层“忽略视图缩放”的图元，每个视频帧重新计算屏幕锚点。

- `core` 固定最多 3 个槽位，保证画布气泡体积可控。
- `extended` 不限制字段；右侧栏以键值表格编辑。
- 工程文件中保存相对路径，整个工程目录可拷贝到其他机器。
- 保存时写 `.tmp` 后 `os.replace`，并将旧文件备份为 `.bak`。

## 5. 关键设计决策

### 5.1 为什么默认改成轻量捕获

v0.1 采用连续视频扫描整图；实测在低配电脑上整图渲染可能内存/耗时过高。v0.2 默认改为：

- 只在稳定、有重叠时拍关键帧；
- 保存 1200px 关键帧 + ORB/边缘特征 + 位姿 + 覆盖多边形；
- 默认不生成整板高分辨率拼图，只生成低分辨率总览；
- 实时定位默认匹配关键帧，周期性用总览做全图校验。

这保留了连续扫描“顺序先验/高重叠”的优点，同时避免一次渲染几百 MB 的整图。全图扫描仍作为独立备用模式保留。

但轻量捕获并非“免费”：

- 帧间误差会累加，需要关键帧质量门控和足够重叠；
- 快速甩动/失焦会造成跟踪失败；
- 长距离往返会产生回环误差，需要回环闭合；
- 总览分辨率受关键帧降采样和画布上限约束；
- 关键帧之间的视场靠相似变换插值；重复纹理可能导致误锁；
- 需要红色覆盖/重叠门控，操作员必须停稳。

这些在 [轻量稀疏建图设计](10_轻量稀疏建图设计.md)、[算法设计](02_算法设计.md) 和 [演进计划](06_硬件集成与演进.md) 中展开。

### 5.2 为什么不用 6DoF/SLAM

相机只做平移+小旋转、PCB 为平面，4 自由度相似变换（tx,ty,θ,s）已经足够。引入 SLAM/PnP 会增加标定、特征管理和稳定性成本，对当前场景收益很低。未来若相机明显倾斜，可升级为单应性（8 自由度）并做相机标定。

### 5.3 为什么气泡不跟随缩放

参数需要始终可读。组件框随板旋转/缩放，但气泡使用 `ItemIgnoresTransformations` 保持固定屏幕尺寸，并在每帧重新计算锚点，避免放大后文字巨大、缩小后不可读。

### 5.4 为什么自动检测只给候选

全新项目没有训练数据，传统视觉无法可靠识别类别/位号。默认检测器只产生“可能含元件的矩形”，强制进入人工核对；这样比伪装成“全自动”更安全。YOLO 适配器预留给有数据后的升级。

## 6. 运行状态

```text
[静态全局图] --打开摄像头/视频/演示--> [实时采集]
       ^                                  |
       |                                  v
       +---- 停止/错误 <---- [跟踪锁定] <-> [暂时跟丢] --> [丢失/隐藏]
                                      |
                              扫描对话框：记录关键帧
                                      v
                              [后台渲染全局图] -> 新工程
```

- `static`：显示整张全局图，可缩放核对，不需要相机。
- `locked`：重叠层正常显示；状态栏显示内点/置信度/耗时。
- `stale`：短暂跟丢，保持上一矩阵，覆盖层降透明度。
- `lost`：矩阵不可用，隐藏覆盖层；等待重新匹配。
- 扫描建图与实时跟踪互斥使用相机画面，但可以在同一实时源上进行。

## 7. 目录与职责

见 README 的工程结构；核心原则：

- `core/` 不导入 PyQt6（`video.py` 也无 UI 依赖），便于离屏测试和未来换前端。
- `ui/` 只做呈现和交互；工程修改通过明确方法回写模型。
- `selftest.py` 覆盖从数据、算法到 UI 的关键链路，打包后仍可运行。
- `tests/` 使用合成 PCB，不依赖私有图片或摄像头。

## 8. 后续扩展点

1. **机台坐标**：实现 `MachinePoseSource`，用串口/网口读取 `(X,Y,Z,θ)`，替代 ORB 输出矩阵；UI 不变。
2. **回环闭合**：扫描最后一张与首张匹配，分配误差或做位姿图优化。
3. **YOLO**：训练 `pcb_component` 数据集，替换 `YoloDetector`；保留人工核对。
4. **相机标定**：棋盘格/远心镜头畸变校正，提升边缘精度。
5. **PySide6 迁移**：解决 PyQt6 GPL 许可约束。
