# 11 虚拟环境与依赖

## 1. 为什么仓库里没有 `.venv`

开源仓库**不应该提交虚拟环境**：

- `.venv` 是平台/机器相关的（Windows 路径、编译好的 DLL、Python 解释器）；
- 本机 `.venv` 约 **389 MB、近 1 万个文件**，会让仓库膨胀几十倍；
- 不同电脑的 Python 小版本、CPU、显卡不同，复制过去的虚拟环境经常不可用；
- 依赖版本已经固定在 `requirements*.txt` / `pyproject.toml`，每个人用命令重建即可。

本仓库只提交源码、依赖清单、脚本、文档和截图；`.venv/` 已在 `.gitignore` 中忽略。

## 2. 环境要求

| 项 | 建议 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| Python | 3.12.x（本项目实测 3.12.9；要求 3.11~3.12） |
| 包管理 | pip（随 Python 自带） |
| 运行库 | 无需单独安装 OpenCV/Qt，pip wheel 自带 |
| 打包 | PyInstaller 6.16.0（仅打包时需要） |

> 本项目不会修改系统 Python。所有依赖只安装到项目内 `.venv`。
> 如果使用 Linux/macOS，源码可运行，但打包脚本和 Windows 摄像头后端按 Windows 编写。

## 3. 从零创建（手动）

在仓库根目录打开 PowerShell：

```powershell
# 如果 PowerShell 阻止激活脚本，只对当前窗口放开
Set-ExecutionPolicy -Scope Process Bypass

# 用 py launcher 指定 Python 3.12；没有 py 就用 python
py -3.12 -m venv .venv

# 激活（二选一）
.\.venv\Scripts\Activate.ps1
# 或在 cmd.exe 中：
# .\.venv\Scripts\activate.bat

python --version
# 应显示 Python 3.12.x

python -m pip install --upgrade pip
python -m pip install -r requirements-dev.txt
python -m pip install -e . --no-build-isolation

python -m pip check
```

`--no-build-isolation` 用于避免 pip 在安装 editable 包时临时联网拉 setuptools；如果网络正常也可以省略。

### 国内网络较慢时

```powershell
python -m pip install -r requirements-dev.txt `
  -i https://pypi.tuna.tsinghua.edu.cn/simple
```

## 4. 一键脚本（推荐）

项目已经提供：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_env.ps1
```

脚本会：

1. 只创建项目内 `.venv`；
2. 安装固定版本依赖；
3. 用 editable 模式安装本项目；
4. 不写入系统 Python、不修改 PATH。

如果已经存在 `.venv`，不要直接删除正在使用的环境；先关闭程序，再删除重建。

## 5. 运行与验证

```powershell
# 启动
.\scripts\run.ps1

# 测试 + 离屏自检
.\scripts\test.ps1

# 打包（会先跑测试）
.\scripts\build.ps1
```

手动运行测试：

```powershell
$env:PYTHONPATH = "D:\obsai2026\src"
$env:QT_QPA_PLATFORM = "offscreen"
$env:QT_QPA_FONTDIR = "C:\Windows\Fonts"
.\.venv\Scripts\python.exe -m pytest -q
```

`QT_QPA_PLATFORM=offscreen` 用于无显示器/CI 环境；正常桌面运行不要设置它。

## 6. 依赖版本

运行时（`requirements.txt`）：

```text
PyQt6==6.9.1
opencv-python-headless==4.12.0.88
numpy==2.2.6
```

开发/打包（`requirements-dev.txt`）：

```text
pytest==8.4.2
pyinstaller==6.16.0
```

为什么固定版本：

- OpenCV 4.12 与较新的 NumPy 存在 wheel/ABI 兼容问题，本项目固定 NumPy 2.2.6；
- PyQt6 6.9.1 是当前测试过的 Qt 版本；
- 避免 `pip install` 自动升级后出现“本机能跑、另一台不能跑”。

升级依赖时请同时更新 `requirements*.txt`、`pyproject.toml` 并跑完整测试。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `Activate.ps1 cannot be loaded` | 使用 `Set-ExecutionPolicy -Scope Process Bypass`，不要改全局策略 |
| `No module named pcb_ar` | 确认已 `pip install -e .`，且运行的是 `.venv\Scripts\python.exe` |
| `ModuleNotFoundError: PyQt6` | 激活环境后重新 `pip install -r requirements-dev.txt` |
| `pip install` 超时 | 使用清华镜像，或配置企业代理；不要跳过版本固定 |
| OpenCV/NumPy 报 ABI 错误 | 删除 `.venv` 后按本文重建，不要混装系统 Python 包 |
| 摄像头打不开 | 关闭占用摄像头的软件；在系统相机中确认设备；试索引 1 |
| 离屏测试中文变方框 | 设置 `QT_QPA_FONTDIR=C:\Windows\Fonts` |

## 8. 与 GitHub 同步

仓库提供了一个不硬编码令牌的同步脚本：

```powershell
$env:GITHUB_TOKEN = "<your-personal-access-token>"
powershell -ExecutionPolicy Bypass -File .\scripts\sync_github.ps1
```

脚本会：

- 用 GitHub API 检查/创建 `biekuaicom/obsai2026`；
- 确认 `.venv` 被忽略，不会把虚拟环境推上去；
- 初始化 git、提交、设置 `origin`、推送 `main`；
- 输出仓库地址。

> 不要把 token 写进脚本、README、`.env` 或提交历史；用完立即在 GitHub Settings 中撤销/轮换。
